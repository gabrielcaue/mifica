# Quando usar cada agente

## modernize-java-assessment
Para diagnosticar riscos, inconsistências e pontos de atenção no código Java. Bom para entender causa provável de erro sem mexer no código.

## modernize-java-security
Para varrer vulnerabilidades, CVEs e dependências Java. Não é o mais indicado para erro funcional de cadastro.

## modernize-java-upgrade
Para atualização de versão de Java, Spring, Maven ou dependências. Útil quando o objetivo é modernização técnica.

## modernize-azure-java
Para temas de migração/adequação Java em Azure. Não se aplica a erro de cadastro.

## modernize-azure-dotnet
Para projetos .NET em Azure. Não se aplica aqui.

## modernize-rearchitecture
Para redesenho de arquitetura. Não é a melhor escolha para debug pontual.

## modernize-fundation
Para base estrutural e preparação de modernização. Não é o foco desse problema.

## modernize-design
Para decisões de design e estrutura. Não é o ideal para investigar esse erro.

## modernize-plan
Para planejar a modernização antes de executar. Útil quando você quer um roadmap, não um diagnóstico imediato.

## modernize-task
Para tarefas pequenas e bem definidas. Pode servir se você já souber exatamente o que mudar.

## modernize-implementation
Para implementar mudanças já definidas. Não é a primeira escolha para descobrir a causa.

## modernize-batch-impl
Para aplicar várias implementações em lote. Só faz sentido depois do diagnóstico.

## modernize-gatekeep
Para revisão/validação de qualidade e conformidade. Útil como etapa final, não para achar a causa do erro.
